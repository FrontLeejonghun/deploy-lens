# Deploy Lens

두 웹사이트를 같은 조건으로 촬영하고 배포 전후의 차이를 확인하는 개인 비교실입니다.

[Deploy Lens 열기](https://deploy-lens-silk.vercel.app)

## 할 수 있는 일

- 데스크톱 1440 × 960, 모바일 390 × 844에서 최대 5개 경로 비교
- 나란히 보기, 드래그 슬라이더, 픽셀 차이 강조, 확대
- 새 콘솔 오류·경고와 실패한 네트워크 요청 확인
- title, description, canonical, robots, h1, lang 비교
- 화면별로 의도한 변경 표시
- 브라우저에 최근 12개 비교 보관, 이미지가 포함된 독립 HTML 보고서 다운로드
- 실제 Chromium으로 촬영하는 Forma 샘플: 홈·요금제에 차이, 소개 페이지는 동일

## 실행

Node.js 24와 pnpm 10.33.4를 사용합니다.

```bash
pnpm install
pnpm exec playwright install chromium
pnpm dev
```

기본 주소는 `http://127.0.0.1:4317`입니다. macOS에 Google Chrome이 설치되어 있으면 해당 실행 파일을 대체 경로로 사용할 수 있습니다. 자동화용 새 프로필을 사용하며 사용자의 브라우저 로그인 정보는 읽지 않습니다.

```bash
pnpm lint          # Oxlint
pnpm format        # Oxfmt
pnpm format:check
pnpm check         # TypeScript 및 서버 구문 검사
pnpm build
pnpm start
```

ESLint와 Prettier는 사용하지 않습니다.

## 비교 범위

페이지를 스크롤해 지연 콘텐츠를 불러온 뒤 **전체 페이지(최대 10,000px)**를 촬영합니다. 한 뷰어를 스크롤하면 A/B가 함께 이동합니다. 문서 높이가 다르면 짧은 쪽 하단을 흰색으로 채워 비교합니다. 무한 스크롤·긴 페이지는 제한 높이까지만 촬영하고 경고합니다. 독립적으로 스크롤되는 내부 패널이나 iframe 안쪽까지 자동으로 펼치지는 않습니다. 모바일은 화면 크기 비교이며 실제 모바일 기기·터치·모바일 User-Agent를 완전히 재현하지 않습니다. 두 환경에 언어 `ko-KR`, 시간대 `Asia/Seoul`, 밝은 테마, DPR 1을 적용합니다. URL에 지정된 언어는 그대로 유지됩니다.

입력한 기본 URL의 경로 뒤에 비교 경로를 붙입니다. 예를 들어 기본 URL `https://example.com/ko`와 경로 `/pricing`은 `/ko/pricing`을 비교합니다. 쿼리 문자열은 비교 경로에 입력하세요.

- 공개 HTTP/HTTPS 목적지와 기본 포트만 허용합니다. 배포 보호는 사용자가 제공한 커스텀 헤더로 접근할 수 있습니다. 로그인 화면·캡차는 자동으로 통과하지 않습니다.
- 폼 제출·로그인은 실행하지 않습니다. GET/HEAD 외 요청과 서비스 워커를 차단하므로 POST 기반 조회 API에 의존하는 페이지는 다르게 보일 수 있습니다.
- 요청 안정화와 화면 내 이미지·폰트를 일정 시간 기다린 뒤 촬영합니다. 계속되는 요청이나 준비되지 않은 에셋은 참고 사항으로 표시합니다.
- CSS 애니메이션·캐럿을 정지하고 영상은 시작 시점으로 되돌립니다. 임의의 타이머·랜덤 콘텐츠까지 결정적으로 고정하지는 않습니다.
- CSS 로딩 실패·미적용 스타일시트·웹폰트 오류는 별도 촬영 경고로 표시합니다. CSSOM insertRule, Shadow DOM adoptedStyleSheets, 지연 스타일 주입을 포함한 검증 샘플을 제공합니다.
- 동적 영역은 CSS 선택자로 제외할 수 있습니다. 각 촬영에서 선택자를 찾지 못하면 참고 사항을 남깁니다.
- 픽셀 차이를 계산한 후 화면 표시용 이미지를 WebP로 압축합니다. 픽셀 수치는 PNG 원본 기준입니다.
- 화면 차이는 버그 판정이 아닙니다. 실패한 HTTP 문서 응답은 성공 결과로 처리하지 않습니다.
- 네트워크의 신규 실패는 호스트를 제외한 경로와 응답 상태로 비교합니다. 환경별 도메인 차이를 줄이는 대신 같은 경로의 다른 외부 호스트 요청을 같은 항목으로 볼 수 있습니다.

## 보호된 dev 환경

새 비교의 **커스텀 헤더**에서 A와 B에 각각 이름·값을 추가합니다. Vercel 환경에는 `x-vercel-protection-bypass`와 해당 프로젝트에서 발급한 Automation Bypass 값을 사용할 수 있습니다. 필요한 경우 `Authorization` 등 서비스가 요구하는 헤더를 추가합니다.

헤더 설정은 실행 중 메모리에만 있고 IndexedDB·HTML 보고서에는 저장하지 않습니다. 재실행할 때 값을 다시 입력해야 합니다. 각 헤더는 해당 환경의 정확한 origin(프로토콜+호스트+포트)에만 전송합니다. 인증 요청의 자동 리다이렉트를 막은 뒤 브라우저가 새 목적지로 이동하도록 하여 다른 출처로 헤더가 이어지지 않게 합니다. 결과에 인증 헤더 원문이나 요청 헤더를 기록하지 않습니다. 대상 페이지 자체가 인증 값을 화면에 출력하면 스크린샷에는 보일 수 있습니다.

`Host`, 연결 제어, 프록시, `Sec-*` 등 브라우저·전송 계층 헤더는 입력할 수 없습니다. 환경당 최대 8개, 값당 2,048자입니다. 헤더를 넣어도 사용자 계정에 권한이 없거나 브라우저 로그인이 추가로 필요한 페이지는 거부될 수 있습니다.

`/api/accessCheck`는 공개된 샘플 값 `x-deploy-lens-demo: preview`로 동작을 검증하는 고정 페이지입니다. 실제 비밀이나 사용자 데이터와 무관합니다.

## 데이터와 배포

`api/compare.mjs`는 Vercel Node.js Function입니다. 한 요청은 한 경로·화면 크기를 비교하고, 브라우저가 순차적으로 여러 요청을 실행합니다. 촬영 결과는 API 응답으로 전달하고 서버의 파일·데이터베이스에 저장하지 않습니다. 결과는 사용자의 IndexedDB에 보관합니다. HTML 보고서는 화면과 URL·오류 정보를 포함하므로 내용을 확인한 뒤 공유하세요.

실제 사이트 요청은 Vercel 서버에서 수행합니다. 대상 사이트는 촬영 요청을 관측할 수 있습니다. Google Fonts에서 UI용 DM Sans를 불러옵니다. 기본 Vercel 요청 로그는 호스팅 서비스의 정책을 따릅니다.

촬영 브라우저는 전용 네트워크 프록시를 사용합니다. 연결마다 DNS 결과를 검사하고 공개 IP에 직접 연결하므로 리다이렉트·서브리소스를 통한 사설망 접근과 DNS 재바인딩을 제한합니다. IP당 분당 24회 및 인스턴스당 동시 작업 2개 제한은 **인스턴스 내부의 보조 제한**이며 분산 환경의 전체 사용량 한도를 보장하지 않습니다. 대규모 공개 운영 시에는 플랫폼 방화벽·지속성 있는 사용량 제한을 추가해야 합니다.

Vercel에서 Chromium의 압축 바이너리는 빌드 시 복사하고, 서버리스 실행 시 임시 디렉터리에서 압축을 풉니다. Noto Sans KR을 포함해 Linux 촬영에서도 한글을 표시합니다.

## 구성

- `src/App.tsx`: 비교 실행, 결과 뷰어, 설정, 기록
- `src/storage.ts`: 브라우저 결과 보관
- `src/export.ts`: 독립 HTML 내보내기
- `api/compare.mjs`: 입력 검증, 실행 제한, 응답
- `server/capture.mjs`: Chromium 촬영과 이미지 비교
- `server/egress.mjs`: 공개 IP만 연결하는 프록시
- `server/specimen.mjs`: 자체 제작한 비교 샘플
- `docs/SPEC.md`: 첫 버전의 동작 계약

Noto Sans KR은 Google Fonts의 배포본을 사용하며 라이선스는 `server/fonts/OFL.txt`에 포함합니다. 샘플 Forma는 실제 서비스 데이터와 무관한 데모입니다.
